2Token embedding (wte) — the learnable parameter & embedding vector size

GPT-2 keeps a learnable matrix wte of shape [V, h]. For each input ID, it looks up a row — a vector of size h=768. This h is the embedding dimension that defines how rich each token's representation is. Every weight downstream is sized relative to h.

# one row per token in the vocabulary wte : Tensor[V, h] = [50257, 768] x = wte[ input_ids ] → Tensor[T, h] = [6, 768]
token_emb[T, h]= [6, 768]

Every row of wte is a learnable 768-dim vector. +38,597,376 params  (V × h)

3Position embedding (wpe) — where in the sequence each token sits

Attention is permutation-invariant — without positions, "cat sat" and "sat cat" would look the same. GPT-2 adds a learnable position vector for each slot 0…1023. For our 6 tokens, we take the first 6 rows of wpe.

wpe : Tensor[P, h] = [1024, 768] pos = wpe[ 0, 1, 2, 3, 4, 5 ] → Tensor[T, h] = [6, 768] x = token_emb + pos # element-wise; shapes match: [6, 768]
x[T, h]= [6, 768]

+786,432 params  (P × h)  The x tensor is now the input to the first transformer block.

4LayerNorm 1 (inside block 1) — stabilize before attention

GPT-2 normalizes each token's 768-dim vector independently (mean + variance along h), then applies a learnable scale γ and shift β, each of size h.

x_ln1 = LayerNorm(x; γ, β) # γ, β ∈ ℝ^768 # shape unchanged: [6, 768]

+1,536 params  (2 × h)

5Attention: build Q, K, V from the hidden state

GPT-2's c_attn is a single big linear layer that produces Q, K, V at once. It multiplies x_ln1 ([T, h]) by a weight matrix W_qkv of shape [h, 3h] and adds a bias of size 3h.

5a — Linear projection

W_qkv : [h, 3h] = [768, 2304] b_qkv : [3h] = [2304] qkv = x_ln1 @ W_qkv + b_qkv → Tensor[T, 3h] = [6, 2304] Q, K, V = split(qkv, h, dim=-1) # each [6, 768]

+1,771,776 params  (h × 3h + bias 3h)

5b — Attention variant: MHA (standard Multi-Head Attention)

GPT-2 uses the original Transformer variant: Q, K, and V all have the same number of heads (n_head=12). That's why c_attn can produce all three with a single h → 3h linear. Later models change this ratio to shrink the KV cache during generation.

this model MHA — one K and V head per Q head

GPT-2 uses the original Multi-Head Attention from "Attention Is All You Need": Q, K, and V each have n_head = 12 heads. Because K and V are the same width as Q, the model packs all three projections into the single c_attn matrix and splits the output into Q, K, V downstream.

MHA n_head n_head GPT-2, GPT-3, BERT, Phi-2, Phi-1.5
Implication for GPT-2: K and V have the full 12 heads × 64 head_dim = 768 width. KV cache during generation stores all 12 K and 12 V heads per layer per token.

For GPT-2, since K/V heads = Q heads = n_head, no special handling is needed. The next step just reshapes.

5c — Split h=768 into 12 heads of 64

Multi-head attention views the 768-dim vectors as 12 parallel "views" of 64 dims each. Pure reshape — no new parameters.

Q = reshape(Q, [T, n_head, head_dim]) = [6, 12, 64] K = reshape(K, [T, 12, 64]) V = reshape(V, [T, 12, 64])

5d — Scaled dot-product attention

For each head, compute how much every token should attend to every other token.

scores = Q @ K.T / √head_dim → Tensor[n_head, T, T] = [12, 6, 6] scores = apply_causal_mask(scores) # "sat" can't see "on"/"the"/"mat" attn = softmax(scores, dim=-1) # rows sum to 1 ctx = attn @ V → Tensor[n_head, T, head_dim] = [12, 6, 64] ctx = reshape(ctx, [T, h]) = [6, 768]

GPT-2 is causal: at each position the model can only attend to earlier (and the current) positions. This is what makes it a left-to-right language model. All math here is parameter-free. 0 params

6LayerNorm 2 + MLP (feed-forward block)

After attention mixes information across positions, the MLP processes each position independently. GPT-2's MLP is a 2-layer feed-forward: h → 4h → h with GELU in between.

x_ln2 = LayerNorm(x; γ', β') # +1,536 params (2 × h — scale + shift) c_fc: W1[h, 4h] = [768, 3072], b1[4h] = [3072] c_proj: W2[4h, h] = [3072, 768], b2[h] = [768] h1 = x_ln2 @ W1 + b1 → Tensor[T, 4h] = [6, 3072] h1 = gelu(h1) # element-wise non-linearity mlp_out = h1 @ W2 + b2 → Tensor[T, h] = [6, 768] x = x + mlp_out # residual

One last LayerNorm, then project the hidden state down the vocabulary dimension. GPT-2 ties the LM-head weight with wte from step 2 — the exact same parameters are reused, so no new weights are added.

3Position information — RoPE, not a learned table

Unlike GPT-2, Llama has no position embedding table. Instead, each attention layer injects position info by rotating Q and K vectors (Rotary Positional Embeddings). The rotation angles are pre-computed from rope_theta=500,000 and the token position — no learnable parameters.

# Position is applied later, inside each attention block (step 5d). # No table, no lookup, no weights.

0 params  This is why Llama can extend to 131,072 tokens of context — no fixed table caps the length.

4RMSNorm (pre-attention) — simpler than LayerNorm

Llama uses RMSNorm instead of LayerNorm. Only a scale parameter γ of size h — no shift β, no mean subtraction. Half the params and slightly faster.

x_norm = x / rms(x) · γ # γ ∈ ℝ^4096, no β # shape unchanged: [6, 4096]

+4,096 params  (h — scale only)

5Attention: Grouped-Query (GQA) with 32 Q heads and 8 K/V heads

Llama uses GQA to shrink KV cache during generation. Q has 32 heads (full width h=4,096), but K and V share just 8 heads each — 4× smaller than Q.

5a — Three separate linear projections (no bias!)

Because K and V are narrower than Q, they can't be packed into one combined c_attn matrix like GPT-2. Llama uses three separate linears, all with attention_bias: false.

q_proj : [h, n_head × head_dim] = [4096, 4096] k_proj : [h, n_kv_heads × head_dim] = [4096, 1024] v_proj : [h, n_kv_heads × head_dim] = [4096, 1024] Q = x_norm @ q_proj → [T, 4096] K = x_norm @ k_proj → [T, 1024] V = x_norm @ v_proj → [T, 1024]

+16,777,216  (q_proj: h × h)  +4,194,304  (k_proj: h × h/4)  +4,194,304  (v_proj: h × h/4)

5b — Attention variant: GQA

this model GQA — K/V share across groups of Q heads

Llama 3.1 8B shares each K/V head across n_head / n_kv_heads = 32 / 8 = 4 Q heads. During generation, only 8 K and 8 V vectors are cached per token per layer instead of 32 → 4× smaller KV cache.

VariantQ headsK / V headsExample models

KV cache per token per layer: 2 × n_kv_heads × head_dim × bytes = 2 × 8 × 128 × 2 = 4,096 bytes (bf16). With MHA it would be 16,384 bytes.

5d — Apply RoPE rotations to Q and K

Rotate each pair of dims in Q and K by an angle that depends on the token's position. This is how Llama "sees" order. V is untouched. No learnable parameters.

5Attention: MLA (Multi-head Latent Attention)

MLA is the single biggest architectural win in DeepSeek-V2. Instead of storing one K and one V vector per head per token (as MHA and GQA do), it compresses the whole K/V representation into a shared low-rank latent. The KV cache stores just this latent + a tiny RoPE sidecar.

5a — Attention variant: MLA

this model MLA — one latent cache per token, shared across all heads

MLA factorizes the K/V projections through a low-rank bottleneck (kv_lora_rank=512). During inference, only the compressed latent is cached — the up-projection to per-head K and V is recomputed from it each step. A small qk_rope_head_dim=64 "decoupled" K component carries the RoPE rotations.

VariantCache per token per layer (scalars)DeepSeek-V2 Lite
MLA kv_lora_rank + qk_rope_head_dim 512 + 64 = 576
KV cache comparison: for the same 16 heads × 128 head_dim = 2,048 scalars per layer that MHA would cache, MLA caches just 576 — about 3.6× smaller — and that ratio grows as you'd add more heads.

5b — Q projection (direct, no compression in Lite)

The full DeepSeek-V2 also compresses Q via q_lora_rank, but Lite sets it to null — Q goes straight from h to the per-head Q space. Each head carries a 128-dim "no-rope" slice and a 64-dim "rope" slice (total 192 dims per head).

6b — Layers 1–26 (DeepSeekMoE block)

this model DeepSeekMoE — fine-grained experts + shared experts

DeepSeek splits the MLP into 66 small experts: 64 routed + 2 shared. Each expert is a mini SwiGLU with moe_intermediate_size=1,408 (about 8× smaller than the dense MLP's 10,944). Per token, the router picks the top 6 of 64 routed experts; the 2 shared experts are always active. All experts' outputs are summed into the residual stream.
